# Shared Evaluation Dataset — tests/dataset/

This folder is the **single shared evaluation set** for the YOLO (Member 1) and Grounding DINO (Member 4)
experiments. Both models must read the **same image files and the same ground truth from here**. Never copy
the images into `detection/experiments/yolo/` or `detection/experiments/grounding_dino/`.

## Folder layout

```text
tests/dataset/
├── README.md                 # this guide
├── dataset_info.md           # verified sources, licenses, versions, mappings, limitations
├── class_mapping.json        # CakGo categories <- original source labels (committed)
├── prepare_dataset.py        # download / build / fetch / verify (committed)
├── manifest.csv              # one row per evaluation image (generated by build, committed)
├── annotations/
│   ├── ground_truth.json     # all original boxes per image, xyxy pixels (generated, committed)
│   └── selection_report.json # counts, shortfalls, seed, skipped duplicates (generated, committed)
├── images/                   # evaluation images (generated, NOT committed, see .gitignore)
│   ├── wallet/  keys/  glasses/  remote_control/  negative/
└── .cache/                   # raw Roboflow exports, thousands of images (NOT committed)
```

Only metadata goes into git. Images are re-created locally and checked against the `sha256` column of
`manifest.csv`, so every member ends up with byte-identical files.

## 1. One-time setup (every member)

```bash
pip install requests pillow
```

1. Create a free account at <https://roboflow.com> and copy your key from *Settings → API Keys*.
2. Set it as an environment variable for your shell session. **Never commit it, never paste it in code or docs.**
   - PowerShell: `$env:ROBOFLOW_API_KEY = "<your key>"`
   - bash: `export ROBOFLOW_API_KEY=<your key>`
3. Download the primary export (about 9.9k images, a few hundred MB) into `tests/dataset/.cache/`:

```bash
python tests/dataset/prepare_dataset.py download --source objects_in_house
# Only if build reports shortfalls that the secondary dataset can fill:
python tests/dataset/prepare_dataset.py download --source home_item_detection
```

No API key? On the dataset page choose *Download Dataset → version 5 → COCO JSON → Download zip* and run
`python tests/dataset/prepare_dataset.py download --source objects_in_house --zip <downloaded.zip>`.

## 2a. Dataset owner: build the subset (run once)

```bash
python tests/dataset/prepare_dataset.py build
python tests/dataset/prepare_dataset.py verify
```

`build` is deterministic (fixed seed `cakgo-eval-v1`) and:

- takes candidates only from the **test and valid** splits (train is left untouched for possible later fine-tuning),
- fills Wallet 15, Keys 15, Glasses 15, Remote control 15 and Target-absent 10 (targets, not hard limits),
- prefers images that contain only one target category,
- skips images derived from the same original photo, and near-duplicates (dHash Hamming distance ≤ 6),
- copies the selected files **byte-for-byte** (no resizing, no re-encoding) and keeps **all** original labels,
- uses the secondary dataset only to fill shortfalls, and records any remaining shortfall in `annotations/selection_report.json`.

Then:

1. Visually review the images (especially `negative/`, which could contain an unlabeled target) and set
   `review_status` in `manifest.csv` (for example `ok` or `excluded: <reason>`). Optionally fill `testing_condition`.
2. Record the final counts and shortfalls in [dataset_info.md](dataset_info.md).
3. Commit `manifest.csv` and `annotations/`. Do not commit `images/` or `.cache/`; `.gitignore` already excludes them.

## 2b. Other members: reproduce the exact same files

After pulling the committed `manifest.csv`:

```bash
python tests/dataset/prepare_dataset.py download --source objects_in_house   # step 1, once
python tests/dataset/prepare_dataset.py fetch    # copies exactly the files listed in manifest.csv
python tests/dataset/prepare_dataset.py verify   # sha256 check of every image
```

`fetch` never re-selects; it reads `source_split` and `source_filename` from the manifest. If `verify` reports a
sha256 mismatch (for example, Roboflow regenerated the export), do not continue. Ask the dataset owner to share the
`images/` folder through team storage, then run `verify` again.

## manifest.csv columns

| Column | Meaning |
|---|---|
| `image_id` | Stable ID, e.g. `wallet_003` |
| `file_path` | Path relative to `tests/dataset/`, e.g. `images/wallet/wallet_003.jpg` |
| `sha256` | Checksum of the image file |
| `width`, `height` | Pixel size of the file |
| `target_category` | `wallet`, `keys`, `glasses`, `remote_control` or `negative` |
| `contains_categories` | All CakGo categories present in the image (`;`-separated) |
| `gt_boxes_xyxy` | JSON list of `[x1, y1, x2, y2]` pixel boxes of the target category |
| `num_gt_boxes` | Number of boxes in `gt_boxes_xyxy` |
| `source_labels` | Original label names in the image (`;`-separated) |
| `annotation_available` | `yes` / `no` |
| `testing_condition` | `unknown` by default (sources provide no lighting/clutter metadata) |
| `review_status` | `unreviewed` until a human checks the image |
| `source_dataset`, `source_url`, `source_version`, `source_split`, `source_filename`, `license` | Provenance |

`annotations/ground_truth.json` contains every original box for each image (`source_label`, mapped
`category` or `null`, `bbox_xyxy` in pixels, and the untouched source `bbox_source_coco_xywh`).
The box format matches `docs/API_CONTRACT.md` (`[x1, y1, x2, y2]`, original image pixels).

## How the YOLO experiment uses it

`detection/experiments/yolo/run_inference.py` reads `tests/dataset/manifest.csv` and loads each image from
`tests/dataset/<file_path>`. `evaluate.py` reads `tests/dataset/annotations/ground_truth.json`.
See [detection/experiments/yolo/README.md](../../detection/experiments/yolo/README.md).

## How the Grounding DINO experiment can use it

This is guidance only; the Grounding DINO code is owned by Member 4 and is not part of this change.

- Read the same `tests/dataset/manifest.csv` and open images from `tests/dataset/<file_path>` (relative to the
  repository root). Do not copy, resize or re-save the files during preparation; any model-specific
  preprocessing belongs inside the model's own inference code.
- Use `annotations/ground_truth.json` for evaluation. Its boxes are in the same pixel coordinates as the image files.
- The category names and display names in `class_mapping.json` (`wallet`, `keys`, `glasses`, `remote_control`)
  can be used to build text prompts. Prompt wording is Member 4's choice and should be recorded with the results.
- Run `prepare_dataset.py verify` before each benchmark run, and record the `sha256` of `manifest.csv` with the
  results so that both runs can be shown to use the same data.

```python
import csv, json
from pathlib import Path

DATASET = Path("tests/dataset")
rows = list(csv.DictReader(open(DATASET / "manifest.csv", encoding="utf-8")))
gt = {g["image_id"]: g for g in json.load(open(DATASET / "annotations/ground_truth.json", encoding="utf-8"))["images"]}
for row in rows:
    image_path = DATASET / row["file_path"]   # identical file for both models
    target = row["target_category"]           # "negative" = no target present
```

## Rules

1. Both models use exactly the files listed in `manifest.csv`; no per-model copies or edits.
2. Keep original source labels; mappings live only in `class_mapping.json`.
3. Do not commit images, raw exports, model weights or API keys.
4. Do not fabricate annotations or results. Missing categories or samples are documented, not invented.
5. ORBIT is a future option and is not downloaded at this stage.
