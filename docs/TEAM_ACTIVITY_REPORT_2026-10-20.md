# IC-PBL 팀활동보고서

## 미팅 개요

| 항목               | 내용 |
|--------------------|------|
| 팀이름               | 찾고 (CakGo) — AI 기반 실내 물건 찾기 보조 서비스 (AI-powered Indoor Object Finding Assistant) |
| 일시               | 2026년 10월 20일 (화) |
| 참석자             | 팀원 전원 (나즈미 – 데이터셋·YOLO·실제 사진 테스트·데모 실행, 김철연 – Grounding DINO·카메라-백엔드 연결·추가 모델 실험, 오가암 – 휴대폰 화면·DINO 연동·휴대폰 테스트, 상싱위 – 백엔드 API·한국어 음성·문서) |
| 문제해결과정       | 공개 데이터셋 테스트에서는 파인튜닝한 YOLO가 가장 좋은 결과를 보였으나, 실제 휴대폰 테스트에서는 물건을 거의 찾지 못하는 문제를 발견함. Grounding DINO는 물건은 잘 찾았지만 마우스·키보드 등을 리모컨으로 착각하는 오탐 문제가 있어, 비슷한 물건 이름을 함께 묻는 '멀티 프롬프트' 방식으로 오탐을 줄임. 이후 팀원이 직접 찍은 실제 사진 94장으로 모델을 공정하게 비교하여 최종 모델을 결정함 |
| 본 미팅의 주요활동 | • 전체 모듈 통합 결과 확인 (휴대폰 카메라 ↔ 백엔드 ↔ 탐지 모델 ↔ 한국어 음성 안내, 실제 아이폰에서 동작 확인)<br>• 1차 휴대폰 테스트 결과 공유 및 개선 사항 반영 확인 (음성 안내 빈도, 글자 크기)<br>• 실제 사진 94장 테스트 결과 비교 및 **최종 탐지 모델 결정: Grounding DINO 멀티 프롬프트**<br>• 프로젝트 문서 최신화 및 최종 발표 준비 업무 분담 |

## 진행 사항

| 항목                         | 내용 |
|------------------------------|------|
| 이번 미팅에서 한 일(활동 내용) | • **데이터셋 확정 및 전처리**: 공개 데이터셋 *Objects In House* v5 (CC0) 선정, 공유 테스트 이미지 70장 구성(물건별 15장 + 물건 없는 사진 10장), 중복 이미지 제거 및 테스트 이미지가 학습에 섞이지 않도록 하는 누수 방지 처리<br>• **YOLO 파인튜닝**: 4개 물건으로 YOLO 학습(v1: 60 epoch, v2: 120 epoch + 데이터 증강). 데이터셋 테스트에서는 평균 AP50 0.94로 우수했으나, 지갑에서 과적합 확인(학습 사진 100% vs 새 사진 63%)<br>• **1차 휴대폰 테스트 (10/19, iPhone 15 Pro)**: 전체 흐름 동작 확인. 파인튜닝 YOLO는 실제 사진 4장 중 1장만 찾음, Grounding DINO는 4장 모두 찾았지만 마우스·키보드·공유기를 리모컨으로 오탐<br>• **멀티 프롬프트 개선**: 4개 물건과 비슷한 물건 이름(마우스, 노트북, 키보드 등)을 함께 물어보는 방식 적용. 검증 사진 기준 오탐 비율 53~94% → 5~16%로 감소 (추가 학습 없음, 속도 동일)<br>• **실제 사진 94장 비교 테스트**: 팀원 3명이 직접 촬영한 사진으로 모든 모델을 같은 조건에서 평가. 균형 점수(찾은 비율 − 오탐 비율) YOLO 0.34, **DINO 멀티 0.48**, DINO 단일 0.28<br>• **휴대폰 시간 측정**: 물건을 비춘 뒤 박스가 표시되기까지 중앙값 2.7초 (30회 측정), 음성 안내는 그보다 조금 뒤에 나옴 |
| 이번 미팅에서 한 일(조치 사항) | • **최종 모델 결정**: Grounding DINO 멀티 프롬프트(기준값 0.35)를 앱의 탐지 모델로 확정<br>• **사용자 의견 반영**: 같은 결과가 두 프레임 연속으로 나올 때만 음성 안내, "보이지 않습니다"는 최대 10초에 한 번 / 글자 크기 확대<br>• **데모 준비**: 한 번의 실행으로 백엔드·프론트엔드·휴대폰 접속 링크(HTTPS)를 모두 시작하는 스크립트(`scripts/start_demo.cmd`) 마련<br>• **문서 최신화**: "데이터셋 미정" 안내를 확정된 데이터셋·모델 정보로 교체, 최종 결과 분석 및 한국어 발표 자료 초안 작성 (`docs/2026-10-20/`)<br>• **개인정보 보호**: 팀원 실제 사진은 GitHub에 올리지 않고 비공개 드라이브에서만 관리, 결과는 집계 수치만 공개<br>• **추가 실험 (미팅 이후 10/20~21, 김철연)**: 최신 모델 YOLOE-26, SAM 3 및 예시 사진 등록(퓨샷) 방식 비교 → Grounding DINO 멀티보다 정확도와 속도를 모두 앞서는 방법은 없음을 확인, DINOv3 검증 단계가 오탐을 추가로 줄이는 유망한 방법으로 확인됨 (오탐 24 → 8 / 220) |
| 논의 사항                    | • **데이터셋 점수와 실제 성능의 차이**:<br>  - 공개 데이터셋 사진은 깔끔한 상품 사진이라, 물건이 많고 조명이 다른 실제 방과 차이가 큼<br>  - 결론: 모델 선택은 데이터셋 점수가 아니라 **실제 휴대폰 사진 테스트**를 기준으로 하기로 함<br>• **평가 기준**: 화면을 보기 어려운 사용자에게는 틀린 방향 안내가 "보이지 않습니다"보다 더 위험하므로, 찾은 비율과 오탐 비율을 함께 보는 균형 점수를 사용하기로 함<br>• **남은 한계**: 먼 거리(2/8)와 어두운 곳(4/8)에서 약함, 리모컨 오탐(21%), GPU가 있는 노트북 필요. 실제 사진에서 DINO가 그린 박스 위치는 아직 수작업 검증 전이므로 **예비 결과**로 발표하기로 함<br>• **진동 안내 기능**: 안드로이드는 구현 가능하나 아이폰 브라우저는 미지원, 발표 전 시간이 부족하여 향후 과제로 보류 |
